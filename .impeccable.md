## Design Context

### Users

Two distinct audiences using the same product:

**Respondents** (primary, user-facing at `/s/[surveyId]`)
- **Context:** Arriving from a link (often sent by a researcher), most on mobile, most using the product exactly once. Have 5–20 minutes, not much more.
- **Job-to-be-done:** Be heard. Share real feelings about a product or experience without the fatigue of a 55-question form.
- **Emotional goal:** Feel *listened to* and *respected* — the opposite of the grind of SurveyMonkey. The AI should feel like a thoughtful interviewer, not a questionnaire.

**Admins** (secondary, at `/admin`)
- **Context:** Desktop, task-oriented, repeat sessions. Creating surveys, checking responses, syncing to Notion.
- **Job-to-be-done:** Configure → publish → monitor. Efficient, no hand-holding needed.
- **Emotional goal:** Confidence and control. The interface should feel like a professional research tool, not a no-code toy.

### Brand Personality

Three words (codified in [src/app/globals.css:4](src/app/globals.css)):

1. **科技 / Tech** — modern, precise, considered. Geist typeface, tight tracking, OKLCH-adjacent palette, soft shadows over hard borders.
2. **可靠 / Reliable** — consistent, predictable, never flashy where seriousness is warranted. No bouncy springs on "Submit" buttons.
3. **温暖 / Warm** — counter-balances the tech. Orange `#F59F00` warm accent, breathing glow on the avatar, quirky typing phrases, human microcopy. The AI interviewer has personality, not corporate cheer.

**Voice:** conversational but not casual. Like a smart friend with a clipboard — curious, low-pressure, occasionally witty, never flip.

**Emotions to evoke:** trust → curiosity → being-heard → closure. In that order, across the interview arc.

### Aesthetic Direction

**Visual tone:** Minimal with depth. Lean surfaces with meaningful shadow (`--shadow-card`, `--shadow-glow-warm`, `--shadow-glow-blue`) and subtle gradient hero treatments (`--gradient-hero`). Never flat-and-dead; never over-decorated.

**References (what we want to feel like):**
- **Linear** — restraint, density, motion that serves rather than announces itself.
- **Stripe** — warmth carried through color and typography rather than illustrations.
- **Raycast** — spring-driven micro-interactions, keyboard-first efficiency on the admin side.
- **Anthropic Claude product surfaces** — the AI-as-companion tone, not AI-as-mystery-box.

**Anti-references (what we explicitly avoid):**
- **SurveyMonkey / Google Forms** — bureaucratic, formy, "please check the box" tone. Our reason to exist is to *not* be this.
- **Typeform-style over-animated flow** — beautiful but noisy; a conversation is not a slide deck.
- **Generic SaaS dashboard templates** — bg-gray-50, bg-blue-600, soulless card grids.
- **Hyper-cute illustration-heavy apps** — undermines the trust the interviewer role needs.
- **"AI-slop" defaults** — Inter font, purple gradient hero, cards nested in cards, bounce easing on every transition.

**Theme:** Both light and dark, driven by `prefers-color-scheme`. Full token parity already in [globals.css](src/app/globals.css). Avoid mode-specific hardcoded colors.

### Design Principles

Five principles that should guide every design decision in this project. When unsure, apply them in this order:

1. **Depth over breadth.** The interview philosophy applies to the UI too: do 3 things exceptionally well rather than 20 things okay. A single polished micro-interaction beats ten mediocre ones. Resist the urge to decorate every surface.

2. **Warm technology.** Pair every technical signal (gradient, shadow, tight grid) with a human signal (warm accent, microcopy, breathing glow, gentle easing). Pure cold tech = feels corporate. Pure warmth = feels toy-like. Always both.

3. **Speak human.** Microcopy, empty states, errors, and confirmations should sound like a person wrote them — specific, a little warm, never generic ("Something went wrong" is a failure). This is how the product differentiates from form-based competitors.

4. **Respect the moment.** Animation durations match the weight of the moment: 100–150ms for micro-interactions (hover, focus, send), 200–300ms for standard UI (cards, modals, transitions), dramatic (>300ms) only for earned milestones like interview completion. No bounce easing on UI-mechanical actions; reserve it for celebration.

5. **Token-driven, systematically.** All colors, spacing, radius, shadows, and typography flow through CSS custom properties in [globals.css](src/app/globals.css). Hardcoded Tailwind utilities like `bg-gray-900` or `text-blue-600` are bugs. If a value doesn't have a token, add a token rather than inlining.

### Register Map (Brand vs. Product mode)

Impeccable commands apply different vocabulary depending on whether work is **brand** (expressive, marketing-adjacent) or **product** (functional, task-oriented). This project uses both:

| Surface | Register | Rationale |
|---|---|---|
| `src/app/s/[surveyId]` (welcome, chat, completion) | **brand** | First impression, emotional arc, single-session stakes |
| `src/components/chat/*` | **brand** | Part of the respondent experience |
| `src/app/admin/*` | **product** | Task interface for professional users |
| `src/components/ui/*` (shared) | **product** primitives used by both | Neutral, flexible, composed by the brand/product layers above |

Apply this implicitly when `/polish`, `/animate`, `/critique`, `/bolder`, `/quieter` are run on a specific directory.

### Accessibility Baseline

- **WCAG:** AA minimum for all text against its background. Admin section currently violates this in several places (`bg-yellow-100 text-yellow-800` — borderline at small sizes); Phase 1 token migration fixes this.
- **Motion:** `prefers-reduced-motion: reduce` already handled globally ([globals.css:273-282](src/app/globals.css)). New animations must degrade gracefully under this query.
- **Touch targets:** 44px minimum on mobile. NPS 0–10 pills currently fall short — Phase 2 fix.
- **Focus:** Visible focus rings using `--accent-primary` with sufficient contrast. Never `outline: none` without a replacement.
- **Screen readers:** Chat message list uses `role="log"`. Individual cards need `aria-describedby` linking options to question (Phase 2 fix).
